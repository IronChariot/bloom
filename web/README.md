# Bloom web

Bloom is a hosted brainstorm canvas for people and AI agents. The canvas uses SVG with motion-driven elastic deformation. Nodes get smaller by generation; labels scale down more gently. Linking preserves existing colours and generation sizes.

## Sharing and saving

On Cloudflare, sign in through Cloudflare Access email login. Every board has its own owner and membership list. Share board creates an invitation URL; the owner can revoke invite links or remove members. Invited people must also be allowed by the Cloudflare Access policy. The browser Worker verifies signed Access JWTs before serving the shell, assets or API. Human sign-in and browser-to-agent collaboration are verified; see [Cloudflare setup](CLOUDFLARE.md). The older private Site remains available separately with ChatGPT sign-in.

Changes are saved to D1. On the Cloudflare deployment each open board also has a live room (a `BoardRoom` Durable Object, one per board) reached over a WebSocket at `/api/boards/:id/live`. It pushes other people's cursors, selections and "revision N was committed" nudges, so edits appear at once and a tab with a live connection checks for edits only every fifteen seconds, as a safety net. The room stores nothing durable and hibernates between messages. Without a room (the Sites deployment, or while reconnecting) tabs fall back to checking on their own: active visible tabs check for edits every two seconds. After thirty seconds without input and no active selections they check every fifteen seconds; hidden tabs stop checking. Returning to a tab, interacting after idle, or reconnecting checks immediately. Failed requests back off up to sixty seconds. Member last-seen is included in the same check and written at most once per twenty seconds per person. Selection and editing presence is independent, with debounced selection changes and a fifteen-second heartbeat while selected or editing. An unchanged response contains small status/presence fields, without the graph, history or image. Graph mutations are atomic. A browser edit names the revision it was made against (`baseRevision`) and is replayed on the latest board, so other people's unrelated changes never block it: moves are last-writer-wins, text and comment edits still check their before-values, and targets someone else has removed are skipped and reported rather than failing the edit. Agents keep the strict content/layout revision checks. An edit conflict preserves text drafts for review.

Undo and redo are per person. Each committed change is stored as a small patch of the ideas, connections and title it touched (`undo_steps`, fifty per person per board). Undo restores only fields that still hold what that change set, so it never overwrites someone else's newer work; it removes an idea it added only if nobody has edited or connected to it since. An agent's edits join the undo history of the account it acts for (the connection key's owner, or the board owner for a board code).

Retained revision snapshots (used by agents' `sinceRevision` reads and the activity list) are capped at fifty entries and 8 MiB of graph data per board, whichever is reached first. Older snapshots are physically deleted in the same transaction as each edit. The migration prunes existing history and filters its stacks consistently. Current board content is preserved. Activity is derived from this retained history rather than stored as an unlimited audit trail.

Node moves, text and colour edits stay visible locally while saving. Queued edits keep their latest appearance when an earlier response arrives; confirmed server revisions and field preconditions still govern writes. Rejected edits reconcile with the server state and show a conflict message. `node tests/web-pending.mjs` from the repository root checks delayed and rejected saves using the real canvas and bridge in headless Chrome with an isolated local test server.

The menu provides new boards, import, download, duplicate, recent boards, JSON Canvas export and close. A downloaded .bloom file is an offline copy; cloud persistence does not depend on downloading. Existing desktop .bloom files import through the menu. Save and export use browser downloads.

**Upload board**, next to Download, restores a `.bloom` download or supported text-node JSON Canvas file into the current board. Its title, graph, styles and petals replace the previous contents as one undo/redo step for the person who uploaded it; the board ID, members, sharing links and agent grants stay in place. The file-menu import and Ctrl+O use the same flow. With no board open, importing creates a board. Pending text edits are saved before the picker opens. Invalid/oversized files and stale revisions are rejected without replacing the board. `node tests/web-import.mjs` verifies an actual browser download/upload roundtrip, undo/redo and failure cases against the real API handlers with isolated SQLite storage.

Users can choose **File menu → Your name…** to save an account-wide display name. Comments (including their edit attribution), activity and board participants use that name. Existing email-attributed comments and activity resolve to the current profile without rewriting graph history or changing account permissions. Profile changes reach open boards through presence sync. Names are optional; an account without a chosen name retains its existing identity label.

Each board member has a colour (`members.color`, the first of eight free on joining). Other people's selected blobs and links get outlines in their colour, dashed while they are typing, with name labels, and their cursors show with a name tag. Cursor positions are sent in board coordinates about fourteen times a second and drawn 110 ms behind, blended between samples, so movement is smooth. The bottom-right corner lists who is on the board, you first; choosing someone moves the view to their pointer or selection. Text editing first acquires an exclusive per-node server lease, then opens the editor using fresh text. A lease lasts 45 seconds, renews every 15 seconds, and is released after save/cancel, board switch or tab close. If connectivity is lost, the local editor stops after a conservative 40-second deadline; unsaved drafts remain available to retry, copy or discard. Selection is advisory; moving/recolouring a locked node and editing unrelated nodes remain allowed. Text replacement/deletion (including agent edits, Undo and import) checks the lease in the same atomic database transaction as the graph write. Presence and locks never advance graph/content/layout revisions or appear in Undo history. Migration `0005_slimy_titania.sql` creates these ephemeral tables.

Collaboration checks: `node --test tests/presence.test.js` and `node tests/web-presence.mjs` from the repository root cover concurrent editors (including separate tabs for the same user), lock expiry, write races, agent protection, draft recovery, labels, and disconnect cleanup. The live MCP smoke test uses a temporary lock on a disposable board.

## Agent access

Agent session provides a one-time Streamable HTTP MCP connection at `https://bloom-mcp.theothersam.workers.dev/mcp`. Configure Hermes, Codex or Claude Code (desktop app or CLI) using **One-time agent setup**, then give the agent a board's 49-character code from **Copy board code**. Redeeming the code stores a persistent grant, so further boards and later visits need no config edits. Each agent gets its own named connection key, listed with its last use and revocable on its own, so adding or removing one agent never disturbs another. Keys belong to an account, and every member of a board can copy that board's code for their own agent. Grants follow membership: `claim_board` accepts a code only from a member's key, and removing a person also stops their agents. The connection key alone has no board access. Board code copies remain stable across browser reloads; pause, replacement and revocation are checked on every call. See [Connecting an agent](AGENT_CONNECTION.md).

Tools: `claim_board`, `list_boards`, `get_board`, `edit_board`, `get_board_image`. Specify the granted boardId and use the content/layout preconditions from get_board for atomic edits, or expectedRevision for a strict whole-board check. Legacy board-specific bearer connections retain their four original tools and `bloom://board/current` / `bloom://board/canvas` resources. Browser WebMCP also exposes get_board and edit_board through the signed-in API when supported.

Remote MCP reads default to compact IDs/text/connections, with optional layout, activity and participants. Select `nodeIds` for targeted verification with incident edges and explicit partial scope. Edits default to exact committed revision receipts containing added/updated entities and deleted IDs. Full reads/responses remain opt-in. Reads also support sinceRevision for net changes with an explicit resync response when retained history is unavailable. See the [batch example and response formats](AGENT_CONNECTION.md#efficient-brainstorming-mcp-05). The existing browser HTTP API and browser WebMCP continue to use full state.

Connections carry an optional label of up to 80 characters, drawn at the middle of the line, above the blobs and at a constant size on screen whatever the zoom. Click a label to rename it, or use the connection toolbar. A selected blob can be grown or shrunk with the toolbar buttons; an explicit size from 0.35 to 3 is the blob's absolute scale and replaces the generation taper, so `size: 1` on every node makes a long chain uniform. Automatic placement checks for collisions, so two branches of the same generation can no longer land on identical coordinates; `get_board(includeLayout: true)` reports any blobs that do cover each other, which an agent can check without a browser. Connections combine solid/dotted patterns with no, forward, reverse or two-way arrowheads. Sprouting defaults to a solid forward arrow. Ctrl-click (also Cmd or Shift) selects multiple blobs or multiple connections; changing a style affects the selection as one undoable batch. Right-click a blob for coloured, emoji or comment petals. Comments support Shift+Enter line breaks and Enter to confirm, with server-stamped author/date on hover. Each blob holds eight petals; drag them between the 45-degree positions to shift neighbours with animation. Click an existing petal to edit, recolour or delete it. `node tests/web-petals.mjs` from the repository root exercises these interactions in Chrome against an isolated test server.

Connection keys are stored hashed. Board tokens have a lookup hash and an AES-GCM-encrypted recovery copy, bound to the board ID, so an owner can copy the same code again. The encryption key lives in the human Worker's `AGENT_CODE_KEY` secret, outside D1. Grants reference the current board-token hash; replacing or revoking a code invalidates all corresponding grants without reconfiguring any agent. The title of the current board appears in the center of the header.

Browser snapshots are generated only when an agent requests an image. A cached image is reused for up to sixty seconds if its graph revision still matches. Otherwise the next visible browser sync sees the request and uploads a PNG; the agent receives explicit stale/missing status and a fifteen-second retry suggestion. Requests coalesce for sixty seconds and only the first matching upload writes to storage. Uploads from old revisions or paused sessions are discarded. Image responses carry their timestamp and graph revision. They contain the SVG canvas; typed but uncommitted text, floating controls and offscreen nodes are not included. Read the structured graph for complete content. Images are resized to a 700 KB base64 budget; full graph JSON is limited to 1 MB of UTF-8 so both fit within D1's row limit.

## Local development

For Cloudflare deployment use `npm ci`, `npm run cf:build` and the commands in [Cloudflare setup](CLOUDFLARE.md). `npm run cf:test` validates Access JWTs and request identity isolation. `node scripts/smoke-cloudflare.mjs` checks the live MCP deployment using a disposable board, then removes it.

The older Sites development path remains available via `npm run install:ci`, `npm run build` and `npm run dev`. That dev server provides the starter's local sign-in flow. Only the legacy Sites route wrappers consume dispatcher identity. Cloudflare entrypoints verify Access JWTs or board tokens; they never trust client-invented identity headers.

The portable preview is on localhost. To test the compiled Worker separately, use a distinct Wrangler persistence directory from the dev server: two workerd processes must not share the same SQLite files. The root repository's tests/web.mjs runs against a test Worker at 127.0.0.1:8787 with synthetic dispatcher identities. Those test headers must never be used as a production authentication mechanism.

## Validation

The parent repository contains graph, deformation and MCP tests plus a browser integration test. The browser suite covers two distinct identities, denied access, invitations, member removal, invite revocation, simultaneous writes, shared undo/redo, MCP tokens and pause, generation sizing, centred auto-height editing, cross-browser updates, browser WebMCP registration/valid-invalid operations, and PNG snapshots. WebMCP registry tests use an injected test registry because the test browser does not natively implement that experimental API.

`node tests/web-efficiency.mjs` from the parent directory checks the actual browser scheduler with a controlled clock, a seeded legacy database migration, live compiled-Worker revision conflicts, fifty undo/redo operations, and demand-driven MCP images. The HTTP test uses the isolated local Worker at port 8787. The steady-state background budget is approximately 1,800 requests per visible active user-hour or 240 per idle user-hour, excluding edits, startup, retries and requested images. Hidden tabs generate no scheduled traffic. Measure CPU on the target Workers account before claiming compliance with the Free plan's per-request CPU allowance; local integration timings are not production CPU measurements.

## Source layout

- `public/canvas/app.js`, `style.css`, `deformation.js`: canvas, gestures and physics ported from the desktop prototype.
- `public/canvas/bridge.js`: browser file/clipboard operations, shared-state synchronization, invitations, snapshot capture and WebMCP.
- `lib/graph.js`: graph validation, colour inheritance on creation, saved generation metadata and operations.
- `lib/boards.js`: D1 access, authorization, revision transactions and shared history.
- `app/api/[...path]/route.ts`: authenticated board API.
- `app/mcp/route.ts`: remote MCP tools and resources.
- `db/schema.ts`, `drizzle/`: schema and deployment migrations.

Boards support text bubbles and typed connections. This iteration does not add live drag ghosts, remote cursors, offline editing, CRDT merging, arbitrary whiteboard shapes or a soft-body mesh solver. Committed moves synchronize; intermediate pointer movements stay local. A conflict requires retrying or reviewing the draft. Screenshots can be stale when everyone closes the board. Total storage still grows with the number of boards, although history per board is bounded.
